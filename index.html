Developer Field Notes

My personal Git & bootcamp reference — commands, habits, and reminders.

Git vs. GitHub

Git is a version-control tool that runs locally on my computer. It tracks changes to my files and lets me save snapshots (commits) of my work.

GitHub is a remote website that hosts Git repositories in the cloud. It's where I back up my code, collaborate, open issues, and review pull requests.

In short: Git is the tool, GitHub is the place I send my Git history to.

The Daily Loop

  1. Edit — change files in my editor.
  2. Stage — git add <file> to mark what goes in the next snapshot.
  3. Commit — git commit -m "message" to save the snapshot locally.
  4. Push — git push to send commits to GitHub.

Command Reference

CommandWhat it does
git initStart tracking the current folder with Git.
git statusShow what's changed, staged, or untracked.
git add <file>Stage a file for the next commit.
git commit -m "msg"Save a snapshot of the staged changes.
git diffShow the exact line changes before staging.
git pushSend local commits to the remote (GitHub).
git pullFetch and merge the latest from the remote.
git branchList branches (or create one).
git checkout -b <name>Create and switch to a new branch.
git log --onelineShow a compact history of commits.
git remote -vShow the remote repositories I'm connected to.
git clone <url>Copy a remote repo down to my computer.
git restore <file>Discard local changes to a file (before staging).

Things I Should Not Commit

  • .env and .env.local — environment files with secrets.
  • API keys, passwords, tokens — any secret. If pushed, treat it as leaked and rotate it.
  • node_modules/ — huge, reinstallable dependency folder.
  • .DS_Store — macOS junk file.

I keep these out using a .gitignore file from the start.
